## 执行指示

3. 逐个生成测试用例，确保可编译/可导入
4. **追加模式**：如果目标测试文件已存在（前序分片已创建），在文件末尾追加新的 TEST/TEST_F，不要覆盖已有内容。保留已有的 #include、fixture 定义和 main 函数
5. 如果文件不存在，新建完整文件（含 #include、fixture、测试用例、main）
6. 生成完毕后停止，不要执行任何 git 操作

## 不可妥协的两条红线（违反等于本次生成作废）

**红线 A — 命名锁死**：每个 `test_cases[].name` 必须原样作为 `TEST_F(SuiteName, <name>)` 或 `def test_<name>(...)` 出现，不得改名、缩短、合并、拆分。

**红线 B — 禁止 mock 被测对象本体**：被测函数、被测类、同模块 private helper、`do_not_mock` 列出的所有符号都必须真实执行。只能 mock 外部依赖（IO/网络/ROS/硬件/时间/随机）。

写完每个 TEST 后做自检：把被测函数 body 删空只留 `return 0;` 时，测试是否仍会通过？如果会，说明被 mock 过头了，必须重写。
